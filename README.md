# からだ記録

からだの異変を **日付 × 部位** で残していく記録アプリです。人体図から痛むところをタップし、症状とつらさを選ぶだけで、その日のログが1件たまります。

**→ https://kuru77.github.io/karada-log/**

依存ライブラリなし・ビルド不要・サーバーなし。記録はブラウザの localStorage に保存され、オフラインでも開けます。
外部に送るのは、自分で使うと決めた次の2つのときだけです。

- **端末間の同期** — Google でログインしたとき、自分の Google ドライブのアプリ専用領域へ（下記）
- **AI相談** — 送信ボタンを押したとき、選んだ範囲の記録を Gemini API へ（下記）

## なぜ人体図なのか

不調は「いつ・どこが」の2軸がそろって初めて意味を持ちます。テキストのメモ帳では、
「右肩が痛い」と書いた日が先月に何回あったかを数え直すことができません。

このアプリは部位を人体図の座標として持つので、記録がそのまま分布として見えます。
前面・背面あわせて46か所と、目・胃・気分・睡眠など図に描けない16項目をチップで選べます。

- 人体図の色は **つらさ（1〜5）** で、濃いほど強い症状です
- 「この日 / 直近30日 / すべて」を切り替えると、慢性的にどこが多いかが一目で分かります

## 記録するもの

| 項目 | 内容 |
|---|---|
| 日付 | 前後の日へ1タップで移動。過去の日にさかのぼって書けます |
| 部位 | 人体図（前面/背面）またはチップから選択 |
| 症状 | 痛み・しびれ・かゆみなど15種のタグを複数選択、自由入力も可 |
| つらさ | 1〜5の5段階（ごく軽い 〜 とても強い） |
| メモ | きっかけ・時間帯・対処などを自由記述 |

同じ日に何件でも記録でき、あとから編集・削除できます。

## 8つの画面

- **記録** — 日付・人体図・入力フォーム・その日の記録一覧（その日の治療・服薬も並びます）
- **治療** — 受診・検査・お薬・リハビリなどの治療歴（下記）
- **履歴** — 部位／症状／期間／つらさで絞り込み、日付ごとにまとめて表示
- **カレンダー** — 月表示。記録のある日に色ドット、タップでその日へジャンプ
- **統計** — 総記録数・記録日数・平均つらさ、部位/症状ランキング、直近12週の推移
- **くらべる** — 部位 × 期間の比較（下記）
- **AI相談** — Gemini API に記録を渡して読み解いてもらう（下記）
- **データ** — 端末間の同期、JSON/CSV書き出し、JSON読み込み、受診メモ用テキスト生成

## 治療歴

症状とは別の記録として持ちます。症状は「その日」に起きるものですが、
お薬やリハビリは**期間**を持つためです。

| 項目 | 内容 |
|---|---|
| 種類 | 受診／検査／処方薬／市販薬／処置・リハビリ／セルフケア／その他 |
| 内容 | 薬名・検査名・受診内容 |
| 医療機関・診療科 | 任意 |
| 期間 | 開始日と終了日。終了日を空にすればその日だけ、「いまも続いている」で継続中 |
| 関連する部位 | 任意。症状の記録と同じ部位名から選べます |
| 効果 | 効いた／やや効いた／変わらない／悪化した |
| メモ | 説明された内容、副作用など |

記録すると、他の画面にも反映されます。

- **記録タブ** — その日に受けていた治療・飲んでいた薬が、症状の下に並びます
- **カレンダー** — 治療のあった日に細い線が入ります（丸は症状、線は治療）
- **受診メモ用テキスト** — 冒頭に「この期間の治療・服薬」がまとまります
- **AI相談** — 同じ期間の治療歴も一緒に送り、開始・終了と症状の変化に重なりがあるかを述べさせます（因果は断定させません）

## 部位 × 期間をくらべる

「最近この部位、増えていないか」を確かめるための画面です。
部位（またはすべて）と期間の長さ（7 / 30 / 90日）を選ぶと、**直近N日** と **その前のN日** を突き合わせます。

- **前の期間との差** — 記録数・記録した日・平均つらさを、増減つきで表示。増えていれば赤、減っていれば緑
- **部位別の増減** — 全部位を `前 → 今` と差分バッジで並べ、悪化した部位が上に来ます
- **推移** — 週ごと／月ごとに12期間ぶんの棒グラフ。棒の高さが記録数、色がその期間の平均つらさ

平均つらさは、どちらかの期間に記録がないと `—` になります。0件の平均を0として扱うと
「つらさが3.0下がった」のような誤った改善に見えるためです。件数の増減がその役割を担います。

## 受診メモ用テキスト

直近30日の記録を、日付順の箇条書きに整形してコピーできます。

```
【からだの記録】2026年8月22日（土） 〜 2026年8月27日（木）
（記録 3件／3日分）

■ 2026年8月22日（土）
  ・頭：つらさ 5/5（ズキズキ）

■ 2026年8月27日（木）
  ・右肩：つらさ 4/5（こわばり、痛み）
    午後から。温めると少し楽。
```

診察の場で「いつからですか」「どのくらいの頻度で」を思い出す必要がなくなります。

## AIに相談する（Gemini API）

たまった記録をそのまま Gemini に渡して、読み解きを手伝ってもらえます。
**APIキーは利用者ごとに用意**します（[Google AI Studio](https://aistudio.google.com/apikey) で無料発行）。

1. 「AI相談」タブでキーを貼り付けて保存
2. 対象の記録（7 / 30 / 90日 × 部位）と、必要なら年代・持病などの補足を入力
3. 「Geminiに送信して相談する」

回答は次の見出しで返るよう指示しています。

| 見出し | 内容 |
|---|---|
| 記録から読み取れること | 時間帯・曜日・部位の偏り、悪化と改善の流れ |
| 考えられる一般的な要因 | 断定せず3つまで。記録のどこが根拠かを明示させる |
| 生活のなかでできる工夫 | 一般的なセルフケア |
| 受診の目安 | どれくらい続いたら、どの診療科か |
| すぐに受診・救急が必要なサイン | 緊急性の高い症状 |

**これは診断ではありません。** 病名を断定させない、記録にない事実を作らせない、受診をためらわせないことを
プロンプトで明示的に制約しています。緊急性の高い症状（強い胸痛、呼吸困難、片側の麻痺、意識障害など）は
AIに聞かず受診・119番するよう、画面上部に常時表示しています。

### 実装上の扱い

- キーは `localStorage` にのみ保存し、リクエストは **`x-goog-api-key` ヘッダー** で送ります（URLに載せると履歴やログに残るため）
- 初回送信時に、記録が外部に送られることを明示して同意を取ります
- モデルは「一覧を取得」でアカウントが使えるものを取得して選べます（既定は `gemini-2.5-flash`）
- 回答のマークダウンは、HTMLエスケープしてから見出し・箇条書き・強調だけを描画します

## データの持ち方

症状は `localStorage` の `karada-log-v1`、治療歴は `karada-log-tx-v1` に、それぞれ配列で入ります。
同期用に、各記録は更新時刻 `_u` を持ち、削除の墓標は `karada-log-deleted` に入ります。

```json
{ "id": "...", "date": "2026-08-27", "part": "右肩", "syms": ["こわばり","痛み"], "sev": 4, "memo": "午後から。", "createdAt": 1787788242392 }
{ "id": "...", "kind": "処方薬", "date": "2026-08-17", "until": "", "ongoing": true, "title": "ロキソプロフェン60mg", "place": "○○整形外科", "part": "右肩", "effect": "better", "memo": "1日2回、食後に服用。" }
```

端末やブラウザを変えると引き継がれないため、データ画面から JSON を書き出しておくと安全です。
書き出しは `{ version: 2, records, treatments }` の形で、症状と治療歴の両方が1ファイルに入ります。
以前の形式（症状だけの配列）も読み込めます。その場合、置き換えを選んでも**治療歴は消しません**
（そのファイルが治療歴を含まないだけで、消してよいという意味ではないためです）。

読み込み時は「いまの記録に追加」か「置き換え」を選べます。CSV は症状と治療歴を別ファイルに、Excel 用の BOM 付きで出力します。

## 端末間の同期（Google アカウント）

パソコン・iPad・iPhone で同じ記録を使えます。データ画面（またはヘッダー右上の「同期する」）から Google でログインします。

- 記録は自分の Google ドライブの **アプリ専用領域**（`appDataFolder`）にある `karada-log.json` 1 ファイルです。ドライブの画面には出ず、このアプリ以外からは読めません。サーバーは使っていません
- 権限は `drive.appdata` だけです。ドライブのほかのファイルには触れません
- 保存の数秒後に自動で送り、アプリを開いたとき・画面に戻ったとき・ネットにつながったときにほかの端末の変更を取り込みます
- 症状・治療の記録ごとに更新時刻を持ち、削除は「墓標」（id → 削除時刻）として残します。同期のたびに双方をマージするので、オフラインで別々の端末から記録しても、**別の記録なら両方残ります**。同じ記録を2台で編集した場合は、あとから保存したほうが残ります
- はじめてログインした端末では、その端末の記録とクラウドの記録を合わせます（どちらも消えません）
- 記録を編集している途中は、取り込みを待ちます（編集中の内容が差し替わらないように）
- 「すべての記録を削除」は、同期しているほかの端末からも削除されます
- ログインの有効期限は約 1 時間です。切れていたらアプリを開いたときに自動で取り直します（10 分に 1 回まで）。取り直せないときはヘッダーの「要ログイン」をタップ
- ログアウトしても、記録はその端末にもクラウドにも残ります
- **AI相談の API キーは同期しません**（端末ごとに入力）
- **Instagram や LINE のアプリ内ブラウザでは Google にログインできません。** Safari や Chrome で開いてください

### 最初に一度だけの設定

研究デスク（lab-desk）で作った Google Cloud のプロジェクトと OAuth クライアントをそのまま使います。
[Google Cloud Console](https://console.cloud.google.com/) で研究デスクのプロジェクトを選び、
**Google Auth Platform → クライアント →（研究デスクで作ったクライアント）** の **承認済みのリダイレクト URI** に次を追加して保存します。

```
https://kuru77.github.io/karada-log/
```

- 承認済みの JavaScript 生成元 `https://kuru77.github.io` と、スコープ `drive.appdata` は研究デスクで登録済みなので、そのままで OK です（念のため **データアクセス** に `https://www.googleapis.com/auth/drive.appdata` があるか確認してください）
- 反映まで数分かかることがあります。追加前にログインすると `redirect_uri_mismatch` と表示されます

## iPhone で使う

iPhone 16 Pro Max（440 × 956pt）を基準に最適化しています。

1. Safari で https://kuru77.github.io/karada-log/ を開く
2. 共有ボタン → **ホーム画面に追加**

追加後はアドレスバーのないフルスクリーンで起動し、機内モードでも開けます（Service Worker がキャッシュします）。

- **セーフエリア対応** — Dynamic Island とホームインジケータを `env(safe-area-inset-*)` で避けます
- **フォーカス時の自動ズームなし** — 入力欄のフォントを16px以上に固定しています
- **タップ領域は最小40px** — 人体図以外のすべての操作要素で確保
- 保存ボタンは画面下に固定。ホームインジケータの上に余白を取っています

## 使い方（ローカル）

`index.html` をブラウザで開くだけです。サーバーもインストールも要りません。
（`file://` で開いた場合、Service Worker は登録されません）

## 注意

体調を記録するためのツールで、診断や治療の判断をするものではありません。
強い症状や急な変化があるときは医療機関にご相談ください。
